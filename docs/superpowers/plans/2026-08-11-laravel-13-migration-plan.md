# Laravel 13 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the eDokter application from Laravel 9 to Laravel 13 on PHP 8.3+ while preserving existing clinical workflows, integrations, routes, middleware behavior, and frontend assets.

**Architecture:** Upgrade the existing application in place on `codex/migrate-laravel-13`, resolving framework and package dependencies one Laravel major at a time. Keep the legacy Laravel bootstrap, HTTP kernel, console kernel, and providers unless a concrete compatibility failure requires a focused change; use checkpoint commits and regression tests to keep every major-version step reviewable.

**Tech Stack:** PHP 8.4 runtime, Laravel 9 → 10 → 11 → 12 → 13, Composer, PHPUnit, Livewire, Laravel Sanctum, Vite, Bootstrap/Sass, MySQL-compatible application database, PDF/BotMan/BPJS integrations.

## Global Constraints

- Work only on branch `codex/migrate-laravel-13`; leave `master` untouched.
- Laravel 13 requires PHP `^8.3`; the final `composer.json` must declare that floor.
- Consult the Laravel 13 Context7 documentation for every Laravel 13 breaking change implemented.
- Do not regenerate the entire Laravel 13 skeleton or replace all configuration files wholesale.
- Do not change production secrets, production `.env` values, database data, or unrelated domain behavior.
- Do not run production database migrations; add a migration only when a concrete framework compatibility issue requires it.
- Preserve public web/API URLs, authentication, Livewire behavior, uploads, PDF endpoints, BotMan routes, and BPJS integrations.
- Never edit `composer.lock` manually; all lockfile changes must be generated by Composer.
- Use `rtk` for shell commands and `apply_patch` for file edits.

## File map

- `composer.json`, `composer.lock`: framework, runtime package, and development-tool constraints and resolved versions.
- `bootstrap/app.php`, `app/Http/Kernel.php`, `app/Console/Kernel.php`: legacy application bootstrapping, middleware order, aliases, and schedules.
- `app/Http/Middleware/VerifyCsrfToken.php` or the Laravel 13 replacement: application CSRF exclusions and base middleware.
- `config/app.php`, `config/sanctum.php`, `config/livewire.php`, and package config files: provider registration, middleware integration, prefixes, and package settings.
- `app/Providers/*.php`, `routes/*.php`, `app/Console/Commands/*.php`: providers, route loading, and scheduled command contracts.
- `app/Http/Livewire/**/*.php`, `resources/views/**/*.blade.php`, and Livewire tests: component APIs, events, lifecycle hooks, uploads, pagination, and Blade integration.
- `tests/Feature/*.php`, `tests/Unit/*.php`, `tests/TestCase.php`, `tests/CreatesApplication.php`, `phpunit.xml`: deterministic test boot and regression coverage.
- `package.json`, `package-lock.json` if present, `vite.config.js`, `resources/js/**`, `resources/sass/**`, `resources/css/**`: frontend build compatibility.
- `docs/superpowers/specs/2026-08-11-laravel-13-migration-design.md`: approved design and acceptance criteria.
